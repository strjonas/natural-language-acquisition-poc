## Q-Learning Comparison

Default experimental condition:

- object positions randomized across episodes,
- object kinds hidden from the learner,
- teacher language visible only in the grounded-teacher condition.

Commands:

```bash
PYTHONPATH=src python3 -m homesocial.experiment --episodes 3000 --eval-episodes 100 --seed 3
PYTHONPATH=src python3 -m homesocial.experiment --episodes 3000 --eval-episodes 100 --seed 4
PYTHONPATH=src python3 -m homesocial.experiment --episodes 3000 --eval-episodes 100 --seed 5
```

Observed result:

The tabular learner does not show a reliable grounded-teacher advantage. Across
these runs, grounded teacher has slightly more teacher utterances and sometimes
slightly more resource use, but mean viability and total reward are not better
than the silent-teacher condition.

## Interpretation

This should not be read as evidence against the core thesis. It is evidence that
the first tabular learner is too weak or too poorly structured to exploit sparse
teacher utterances in a randomized partially observed world.

Current diagnosis:

- The environment now contains grounded, contingent language.
- The language can carry information that is not directly present in the masked
  learner state.
- The tabular agent has no useful memory beyond the current encoded state and
  likely wastes too much exploration budget discovering ask-then-act routines.

## Next Step

Add a teacher-following sanity baseline to prove the utterances are actionable in
principle. Then add the first recurrent trainable agent.

## Recurrent Actor-Critic Baseline

Implemented an MLX-backed recurrent actor-critic baseline:

- GRU recurrent state,
- policy head,
- value head,
- full-episode A2C-style updates,
- masked invalid social/consume actions,
- teacher/no-teacher CLI comparison.

Updated the baseline with:

- richer egocentric visible-object slots instead of only nearest-object summary,
- previous-event observation features,
- action-conditioned next-need, reward-delta, and teacher-utterance prediction
  heads,
- viability-weighted training reward,
- normalized policy advantages,
- safer masked entropy calculation,
- padded batched rollout updates,
- stronger default hyperparameters for local runs.

Command:

```bash
PYTHONPATH=src python3 -m homesocial.recurrent_ac --episodes 200 --eval-episodes 20 --hidden-size 64 --max-steps 120 --seed 3
```

Observed result:

```text
condition,total_reward,steps,mean_viability,min_viability,resource_uses,danger_hits,teacher_utterances
silent_teacher,-0.2870,54.00,0.6594,0.0000,0.00,0.00,0.00
grounded_teacher,-0.2870,54.00,0.6594,0.0000,0.00,0.00,0.00
```

Interpretation:

The recurrent implementation is now in place and runs locally on the M4. But
from-scratch A2C on the randomized hidden-kind setting still does not discover
resource-use behavior in 200 episodes. This is not yet surprising. It means the
next algorithmic step should be curriculum or imitation warmstart from
teacher-following trajectories, plus batched rollout collection before running
long sweeps.

Compute note:

Small runs are feasible on the local M4/16 GB machine. Longer serious sweeps
will need either batching/optimization or external GPU/accelerator compute.

such as bootstrapped returns or GAE, before adding imitation or curriculum.

## PPO/GAE Recurrent World-Model Baseline

Implemented the next non-curriculum architecture step:

- deeper recurrent latent core with layer-normalized encoder/refinement blocks,
- action-conditioned latent transition head,
- next-observation prediction in addition to next-need, reward, and teacher
  utterance prediction,
- GAE value targets with truncated-episode bootstrapping,
- PPO-style clipped policy updates over padded rollout batches,
- CLI controls for `--gae-lambda`, `--clip-ratio`, `--ppo-epochs`,
  `--observation-prediction-weight`, `--width`, and `--height`.

run larger PPO sweeps before introducing online trajectory pretraining or
curriculum.
